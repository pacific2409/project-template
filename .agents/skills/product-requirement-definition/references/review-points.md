# review points

 `docs/persistent/product-requirements.md` を以下の観点でレビューします。
 
 ## Review Report Path
 レビュー結果は以下に出力する。
 ```
docs/reviews/prd-review-report.md
```

## 特有のレビュー観点

- ビジョンと目標
- ターゲットユーザー
- 成功指標(※KPIの指定がある場合)
- 機能要件
- 非機能要件

PRDの品質を確保するため、上記各観点について以下のチェックポイントを確認してください。

### ビジョンと目標
- プロジェクト方針や、プロダクトビジョン、完了条件が明確か
- プロジェクト方針、プロダクトコンセプト、ビジョンおよび目的が、Productとして目指す方向を十分に定義しているか
- 提供する具体的な価値が定義されているか
- ターゲットが明確か

### ターゲットユーザー
- ペルソナやターゲットユーザーについて具体的に定義されているか
- ターゲットユーザーについて、Productが対象とするユーザー像、その課題および期待する解決が十分に定義されているか
- 現在の課題と期待する解決策が明確か

### 成功指標(※KPIの指定がある場合)
- SMART原則に従ったKPIが定義されているか
- 測定方法が明確か
- 達成期限が設定されているか

### 機能要件
- すべての機能がユーザーストーリー形式で記述されているか
- ユーザーが実現したいことや、機能として満たすべき条件が明確化されているか
- 受け入れ条件が明確な形で定義されているか
- 優先度(P0/P1/P2)が明確に設定されているか

### 非機能要件
- パフォーマンス基準の指定がある場合、基準が具体的な数値で定義されているか
- ユーザビリティ基準の指定がある場合、基準が測定可能か
- 信頼性やセキュリティ要件の指定がある場合、各基準が明確か

## 特有のレビュー観点についてのレビュー例

以下は、上記の特有の観点に基づくレビューの例とする。

### **良い点の例**
**✅ 強み**
- 明確なビジョンが測定可能で具体的に記述されている
- ユーザーが実現したいことや、機能として満たすべき条件が明確化されている
- KPIが定量的な指標で定義されている

### **改善点の例**
**⚠️ 改善が必要な点**

機能要件の曖昧さ:
- 問題: ユーザーが実現したいことや、機能として満たすべき条件が不明確な箇所がある
- 推奨: ユーザーストーリーや受け入れ条件を具体化し、要求として必要な振る舞いや条件を明確にする

成功指標の測定方法:
- 問題: 測定方法が不明確
- 推奨: 測定方法とプライバシーへの配慮を明記
