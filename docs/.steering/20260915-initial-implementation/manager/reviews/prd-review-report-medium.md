## 改善が必要な点

### [推奨] 改善推奨

**R-001**: 履歴の技術名を「同じタグ」と判断する基準が不明確。
- **箇所**: 「課題提案の共有履歴」の受け入れ条件
- **理由**: `React` と `react`、前後の空白などの扱いによって選択肢の重複や検索結果が変わり、実装担当と受け入れ確認者で解釈が分かれる。
- **改善案**: 技術名の表記揺れを初回Trainでどう扱うか、要求として必要な範囲だけ決める。例として、大文字小文字と前後空白を同一視するか、入力どおり別のタグとして扱うかを明記する。DBのカラムや索引などの方式は設計に委ねてよい。

**R-002**: 所要時間の有効な入力範囲が不明確。
- **箇所**: 「課題生成条件の入力」の受け入れ条件、「非機能要件 > セキュリティ」の入力検証
- **理由**: 現状の「時間数の数値」は0・負数・小数も許す読み方ができる。これらを課題生成の条件として受け付けるかが不明なため、フォームとバックエンドで判定が食い違いうる。
- **改善案**: 正の値を要するか、小数を認めるかなど、受け入れ可否を判断できる最小限の条件を明記する。上限やUI方式などの詳細は、必要でなければ設計に委ねてよい。
