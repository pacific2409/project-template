# プロダクト要求定義ドラフト

## Overview

DevMenuは、仕事への活用を見据えて新しい技術を個人開発で学ぶシステムエンジニアに向けた、実装課題の提案ツールである。今回のTrainでは、1回の条件入力につき3件の課題を提示し、入力された技術名を使って共有履歴を探せるようにする。主要機能を実際にデプロイし、URLを知る人がアクセスできる状態にする一方、広範な周知や恒久運用は今回の完了条件に含めない。

## プロダクト概要

### 名称
- DevMenu — リスキリング駆動開発ツール

## ターゲットユーザー（ペルソナ）

- 仕事での活用を見据え、新しい技術を個人開発で学ぶシステムエンジニア。
- 業務で接したシステムの採用技術や競合技術、または正確さと反復が求められる開発作業の仕組み化に役立つ技術を、学習テーマの起点にする。

## 目標・完了条件（Goals）

- 条件入力、複数の実装課題の提案、共有履歴での閲覧という主要な利用の流れが動作する。
- リリース・公開を意識したアーキテクチャで主要機能を動作させ、実際にデプロイする。URLを知る人ならアクセスできる状態まで公開する。
- URLを広く周知したり第三者に利用を案内したりせず、他者による利用を今回の目的・完了条件としない。
- インフラを含むデプロイ・公開の作業について、再利用でき、実施履歴を検証しやすい基本的な仕組み化を実現する。
- 悪意あるリクエストや急激な負荷への本番運用水準の備えと、恒久的な稼働・運用は今回の完了条件に含めない。
- 安全対策は、合意した基本的な仕組みが意図どおり構成・動作しているかを基準に確認する。個別対策の網羅性は、このTrainの完了条件としない。
- 開発スタイルで一通りの工程を実施する。

## 機能要件

### 課題生成条件の入力

- 難易度は「初級」「中級」「上級」から選択する。
- 所要時間は、時間数を数値で入力する。

### 実装課題の提案

- 1回の条件入力に対して、実装課題を3件提示する。
- 応答後に提案結果を表示する。生成処理中であることを判別させる表示は、このTrainでは設けない。

### 共有履歴の探索

- 各履歴に、課題の生成条件として入力された技術名を保存する。
- 履歴に存在する技術名を選択肢として表示し、選択した技術名に該当する履歴を閲覧できるようにする。

## 非機能要件

- アプリケーションモジュールはステートレスに設計する。
- このTrainでは生成AI APIの呼び出し回数制限を設けない。将来の導入可能性は排除しない。
- フォームから受け取る値に基本的な入力検証を行う。
- 生成AI APIの認証情報は利用者のブラウザに公開しない。
- 入力値や生成AI APIから受け取った内容を画面に表示する際、スクリプトとして実行されないように扱う。
- 生成結果の応答速度について、このTrainでは数値目標を設けない。
